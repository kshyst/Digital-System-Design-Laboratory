- Design and simulate a UART transmitter and receiver.
- Implement the design as synthesizable, vendor-neutral Verilog in `.v` files.
- Keep the code commented so the interfaces, state machines, counters, and timing decisions are understandable.
- Accept one seven-bit parallel input word per transmitted frame.
- Use a single serial transmit line rather than parallel data transfer.
- Keep the serial line at logic `1` while idle.
- Transmit exactly ten bits per frame.
- Transmit the frame in the exact order `Start`, `Parity`, `D0`, `D1`, `D2`, `D3`, `D4`, `D5`, `D6`, `Stop`.
- Drive the start bit as logic `0`.
- Place the parity bit immediately after the start bit and before all data bits.
- Calculate parity as `D0 ^ D1 ^ D2 ^ D3 ^ D4 ^ D5 ^ D6`.
- Transmit data least-significant bit first, from `D0` through `D6`.
- Drive the stop bit as logic `1`.
- Hold every transmitted symbol for exactly `BIT_TICKS` clock cycles.
- Use 115200 bits per second as the standard transmission rate.
- Use approximately 434 system-clock cycles per bit for a 50 MHz clock.
- Make the clocks-per-bit value configurable through `BIT_TICKS` so simulation can use a smaller value.
- Support the document's `BIT_TICKS = 2` accelerated-simulation example.
- Default `BIT_TICKS` to `434` when no override is supplied.
- Implement the sender as a finite-state machine with idle, start, parity, data, and stop phases.
- Drive `tx = 1` and `busy = 0` while the sender is idle.
- Accept `send_data` only when `new_data` is active while the sender is idle.
- Snapshot `send_data` and its parity when a new frame is accepted.
- Prevent later changes to `send_data` from changing an active frame.
- Keep `busy` active for the entire start, parity, data, and stop sequence.
- Deactivate `busy` only after the complete stop-bit interval.
- Ignore `new_data` assertions while `busy` is active.
- Do not restart, extend, corrupt, or queue another frame when `new_data` is asserted while busy.
- Implement the receiver as a finite-state machine that continuously observes `rx`.
- Remain in the receiver idle state while `rx` is logic `1`.
- Treat a detected logic `0` as a candidate start bit.
- Synchronize the asynchronous `rx` input before using it in the receiver state machine.
- Confirm the candidate start bit near its midpoint so a short low glitch is not accepted as a frame.
- Sample parity, `D0` through `D6`, and stop in that exact order.
- Sample subsequent symbols at the same midpoint phase, one full `BIT_TICKS` interval apart.
- Store the received parity bit separately from the seven received data bits.
- Store each received data bit at its matching bit index.
- Validate the received parity by comparing it with the XOR of the seven received data bits.
- Validate the frame only when both parity is correct and the stop bit equals logic `1`.
- Assert `rec_new_data` after every complete received frame so completion is observable.
- Assert `correct_data` only for a completed frame whose parity and stop bit are both valid.
- Make `rec_new_data` and valid-frame `correct_data` one-clock notifications so consecutive frames are distinguishable.
- Keep `correct_data` low for parity errors and stop-bit errors.
- Do not expose an invalid frame as valid received data.
- Preserve the most recent valid `rec_data` value when a later frame is invalid.
